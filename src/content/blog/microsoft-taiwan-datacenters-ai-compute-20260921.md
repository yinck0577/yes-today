台灣微軟總經理卞志祥今（21）日表示，[微軟](https://www.microsoft.com/zh-tw/)在台資料中心整體架構將由原先2座擴充為**即將開放的4座**，並預估未來2至3年AI算力需求仍可能大於供給。

不過，AI算力短缺不只是GPU供應問題。晶片與記憶體、電力、機櫃、散熱、高速網路及資料中心空間，都可能限制新算力上線速度。微軟9月初在SEMICON Taiwan 2026也提出「Useful Yield」概念，強調AI基礎建設不能只看擁有多少晶片，而要看晶片、記憶體、網路、電力與軟體能否共同轉化成真正可使用的運算能力。

## 微軟台灣資料中心將增至4座，目前知道什麼？

根據中央社9月21日報導，卞志祥表示，微軟在台資料中心原先為2座，整體架構將擴充為**即將開放的4座**，並稱台灣資料中心在微軟全球架構中屬於「Hero Site」，採取「3+1」配置。

目前可確認的資訊如下：

| 項目 | 最新資訊 |
|---|---|
| **台灣資料中心** | 原先2座，整體架構將擴充至4座 |
| **開放狀態** | 新增容量／設施仍屬「即將開放」 |
| **架構** | 微軟稱為「3+1」配置 |
| **Azure在台服務** | 已由初期70多項增至200多項 |
| **AI算力展望** | 微軟估未來2至3年需求仍可能大於供給 |
| **主要客戶** | 政府、醫療、金融及其他企業客戶 |

其中，「3+1」目前不宜自行拆解。

微軟此次並未進一步公開說明「3+1」各自對應哪些設施、位置或功能，因此不能直接解讀為「3座主站＋1座備援站」，也不能把4座實體資料中心直接等同4個Azure Region。

目前微軟Azure官方區域表列出的台灣雲端區域為**Taiwan North**；「資料中心實體設施」與「Azure Region」本身就是不同層級的概念。

另外，Azure在台服務突破200項也不是此次擴建才出現的變化。微軟早在2025年6月就已公布，台灣Azure雲端區域服務由初期約70餘項增加至超過200項，並已有超過百家台灣企業進駐。此次9月21日的新資訊，主要是**資料中心整體架構將從2座擴充至4座，以及卞志祥對未來2至3年算力供需的最新判斷**。

## AI算力為什麼不夠？GPU、電力等6大瓶頸

**因為GPU只是AI算力的一環。即使晶片到貨，如果沒有足夠電力、機櫃、散熱、高速網路與機房空間，也無法立即變成可供客戶使用的算力。**

卞志祥21日指出，算力短缺不單是GPU或CPU問題，還包括電力供給及新機櫃進駐的空間調配；除了興建新資料中心，既有設施也可能需要重新配置。

若從完整AI資料中心來看，可以拆成6項主要瓶頸：

| 瓶頸 | 為什麼重要？ |
|---|---|
| **晶片與記憶體** | GPU、CPU、AI ASIC及HBM等關鍵元件必須到位 |
| **電力** | 高密度AI伺服器需要大量且穩定供電 |
| **機櫃** | 新一代AI伺服器功率與密度提高，既有Rack未必能直接使用 |
| **散熱** | 高密度運算產生大量熱能，冷卻系統必須同步升級 |
| **高速網路** | 大量加速器共同運算，需要高速、低延遲互連 |
| **機房空間** | 晶片、電力都有了，仍需要能實際部署設備的資料中心容量 |

微軟在SEMICON Taiwan 2026提出的「Useful Yield」概念，也把AI基礎建設視為一整套系統，而非單獨追求晶片數量。

微軟指出，下一階段AI基礎建設需要同時整合**silicon、memory、networking、power與software**，並進一步考量冷卻、模型、工作負載及整體機群運作效率。

## 有GPU為什麼還不能直接變成AI算力？

**因為GPU必須裝進完整的伺服器與資料中心系統，取得足夠供電、冷卻、網路與機櫃容量後，才能真正提供運算服務。**

AI伺服器不是把一批GPU送進機房就能直接啟用。

除了GPU本身，大型AI叢集還需要CPU、HBM等記憶體、高速互連、網路交換設備、電源系統與冷卻設備共同運作。

這也是為什麼「GPU出貨量增加」與「雲端可用AI算力立即增加」不能直接畫上等號。

以微軟自研的Maia 200為例，除了AI加速器本身，微軟也重新設計記憶體與網路系統。Maia 200配置216GB HBM3e、7 TB/s記憶體頻寬，並透過專用網路架構串聯大量加速器，顯示大型AI運算的瓶頸不只在晶片算術能力。

## 為什麼AI資料中心這麼耗電？

AI資料中心的耗電問題，核心之一是**運算與功率密度提高**。

大量GPU或AI加速器集中在同一套叢集與機櫃內運作，需要的不只是晶片本身的電力，還包括：

- 冷卻系統
- 網路設備
- 儲存設備
- 備援電力
- 機房基礎設施

而且運算密度提高後，傳統氣冷不一定足以支撐所有高密度設備，液冷等散熱技術的重要性也隨之提高。

因此，AI資料中心的擴張最後往往同時變成**算力、電力與散熱**問題。

## 微軟為什麼要在台灣擴建資料中心？

**資料落地是重要原因之一，但不是唯一原因。**

在地資料中心還能增加區域容量、提供較低延遲的基礎設施，並讓受監管產業依實際服務與合約條件處理資料駐留、法遵、資安及關鍵工作負載需求。

微軟2025年公布的台灣資料中心資訊顯示，在台客戶已涵蓋半導體IC設計供應鏈、金融業、電信、醫療、教育、政府與非政府組織等不同領域。

不同產業需要在地雲端的理由也不完全相同：

| 產業 | 在地雲端主要需求 |
|---|---|
| **金融、醫療、政府** | 法遵、資料駐留、資安、韌性與低延遲 |
| **半導體、高科技** | HPC工程運算、AI訓練／推論、彈性運算容量 |
| **一般企業** | Copilot、AI Agent、資料分析與企業應用 |

對半導體與高科技業來說，需求尤其不只是「資料放在台灣」。

晶片設計、工程模擬、模型訓練與大量資料分析，都可能在特定時間需要大量運算資源。企業如果不需要全年維持相同規模的自建設備，就可能透過雲端取得較具彈性的運算容量。

## 資料中心在台灣，Microsoft資料就全部不出境嗎？

**不等於。微軟在台灣設資料中心，不代表每一項Microsoft 365、Azure或AI服務的所有資料都只在台灣處理與保存。**

實際資料位置仍要依：

- 使用的Microsoft服務
- 租戶所在地與設定
- 授權方案
- Data Residency支援範圍
- Advanced Data Residency（ADR）資格
- Multi-Geo設定
- 備援架構
- 各服務資料處理條款

逐項判斷。

Microsoft Learn目前將台灣列入Advanced Data Residency適用的Local Region Geography之一，但ADR本身也有適用服務與授權條件。

微軟2024年正式啟用Microsoft 365在台資料落地服務時，官方列出的內容包括：

- Microsoft 365 Copilot互動儲存內容
- Teams聊天、頻道與會議訊息
- SharePoint內容及文件
- OneDrive for Business文件
- Exchange Online信箱正文、附件與行事曆

因此，企業若有「資料不得離境」等嚴格法遵要求，仍應確認實際使用服務、租戶與資料位置承諾，不能只因為微軟在台灣有資料中心，就直接推論所有資料都不會跨境。

## 微軟台灣Azure現在所有人都能用嗎？

**還不能只用「有200多項服務」理解成所有Azure客戶都已全面開放。**

微軟Azure目前官方產品區域表仍將**Taiwan North標示為Early Access**，並註明這類區域目前只提供Early Access客戶使用。

微軟2025年10月也曾說明，Taiwan North的Azure服務已開放部分客戶使用，並預計於2026年擴大一般可用性。

因此，即使微軟已公布台灣Azure服務超過200項，也不代表現在任何Azure帳號、任何服務或任何SKU都能自由選擇Taiwan North。

實際使用前，仍應確認Azure官方各產品區域頁及帳號資格。

## 哪些產業最需要台灣在地AI算力？

目前在地雲端與AI算力需求，大致可以分成兩種不同方向。

金融、醫療與政府機關，更重視**法遵、資料駐留、資安與韌性**；半導體及高科技產業則可能更關注**高效能運算、工程模擬、AI模型與彈性算力**。

微軟2025年公布，在台資料中心已吸引超過百家台灣企業進駐，客戶涵蓋前五大半導體IC設計供應鏈、前十大金融業、電信、醫療、教育與政府單位。

卞志祥21日也表示，目前台灣資料中心已有許多企業客戶，其中包括政府、醫療、金融等受到高度管制及涉及資料主權的產業。

## 微軟不用Nvidia GPU了嗎？Maia 200自研晶片在做什麼？

**不是。微軟目前採取的是異質運算架構，自研Maia系列AI加速器與[NVIDIA](https://www.nvidia.com/)、[AMD](https://www.amd.com/)硬體並存。**

微軟2026年推出第二代AI加速器**Maia 200**，主要針對大型AI推論設計，目前已用於Microsoft Foundry、Microsoft 365 Copilot等工作負載，也可支援多種大型模型。

微軟最新財報電話會議也明確表示，公司持續擴充自研晶片，同時使用NVIDIA與AMD最新硬體，並計畫部署AMD Helios及NVIDIA Vera Rubin等下一代AI基礎設施。

因此，不能簡化成「微軟開始自研晶片，所以不需要Nvidia GPU」。

更準確的方向是：

> **大型雲端業者正採取異質運算策略，讓NVIDIA、AMD GPU與自研AI加速器並存，再依模型、推論需求、成本、效能及供應狀況配置不同硬體。**

Maia 200本身也說明了記憶體為什麼是AI算力的重要環節。它採用216GB HBM3e及7 TB/s記憶體頻寬，微軟強調大型模型除了需要運算核心，也必須持續把大量資料快速送進加速器。

## 資料中心從2座變4座，AI算力就翻倍嗎？

**不能這樣算。**

目前公開資訊沒有完整揭露4座資料中心各自的：

- 電力容量
- GPU／AI加速器數量
- 機櫃數量
- AI伺服器部署量
- 網路容量
- 實際運算效能

因此，不能用「資料中心座數從2變4」直接推導「AI算力增加一倍」。

甚至同樣是一座資料中心，部署傳統企業雲端伺服器，與部署高密度AI叢集，可提供的AI運算能力也可能完全不同。

所以這次「2座擴充至4座」能確認的是**微軟正在增加台灣資料中心基礎設施規模**，目前沒有足夠公開資料可以換算實際新增多少AI算力。

## 微軟資料中心擴建，對一般使用者有什麼影響？

短期內，資料中心從2座擴充至4座，並不代表一般人的Copilot會突然變快一倍。

比較可能出現的影響包括：

**第一，在地企業雲端容量增加。**  
更多基礎設施可支撐企業Azure、AI及其他雲端工作負載。

**第二，受監管產業部署選項增加。**  
金融、醫療、政府等產業可依實際服務條件與法規需求，評估更多在地部署方案。

**第三，部分在地工作負載可能降低延遲。**  
對支援在台部署，而且工作負載實際使用台灣區域的服務而言，較接近使用者的基礎設施有機會降低網路延遲。微軟2025年曾表示，其台灣區域資料中心具備低於10毫秒的低延遲能力，但這是基礎設施能力描述，不代表每一名Microsoft 365或Copilot使用者都會得到相同效果。

**第四，支撐更多AI服務需求。**  
企業導入Copilot、AI Agent與生成式AI後，推論與資料處理需求增加，資料中心容量也必須同步擴張。

## AI算力荒還會多久？

**依卞志祥9月21日的判斷，未來2至3年AI算力需求仍可能大於供給。**

但這是微軟主管對未來供需趨勢的預估，**不是產業已經確定「還會缺貨2至3年」的時間表**。

目前可以確定的是，AI算力擴充已經不只是「多買GPU」。

晶片到貨後，還必須有記憶體、電力、機櫃、散熱、高速網路與資料中心空間配合，才能真正轉換成企業與使用者可取得的運算服務。

這也說明為什麼在AI基礎建設競賽中，外界除了關注NVIDIA、AMD與自研AI晶片，也開始把焦點放到**HBM、電力、液冷、網路與資料中心容量**。

至於供需缺口還會維持多久，現階段能確認的是卞志祥的最新判斷：**未來2至3年，AI算力需求仍可能大於供給。**
